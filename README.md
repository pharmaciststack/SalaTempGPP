# Sala-TempGPP — ระบบติดตามอุณหภูมิยาตามหลัก GPP

ใช้เครื่องวัดอุณหภูมิสำเร็จรูป (**SwitchBot** หรือ **Tuya/Smart Life**) ในห้องเก็บยาและตู้เย็นยาทุกสาขา
Google Apps Script จะดึงค่าทุก 15 นาทีแล้วบันทึกลง Google Sheets แสดงผลบนเว็บ (GitHub Pages)
แจ้งเตือนเข้า **กลุ่ม LINE** ทันทีที่ผิดเกณฑ์หรือเครื่องขาดการเชื่อมต่อ สรุปรายวันเวลา 08:00 และส่งรายงาน PDF รายเดือนสำหรับการตรวจ GPP

```
เครื่องวัด ──> Cloud ของยี่ห้อ ──(Apps Script ดึงทุก 15 นาที)──> Google Sheets
                                         │
      หน้าเว็บ (GitHub Pages) <── API ───┤──> LINE Messaging API (กลุ่มสาขา + กลุ่มส่วนกลาง)
                                         └──> Drive: ค่าดิบรายเดือน + รายงาน PDF
```

> **LINE Notify ปิดบริการแล้ว (31 มี.ค. 2025)** ระบบนี้จึงใช้ LINE Official Account + Messaging API

## ทดลองใช้งานบนเครื่อง (ไม่ต้องมีเครื่องวัดจริง)

```bash
python -m http.server 3010
```

เปิด http://localhost:3010 แล้วกด "เข้าสู่ระบบทดสอบ" หน้าเว็บจะรันโค้ด backend จริงในเบราว์เซอร์ด้วยบริการ Google จำลอง
มีเครื่องวัดจำลอง 7 จุดใน 3 สาขา พร้อมข้อมูลย้อนหลัง 7 วัน ส่วน LINE/อีเมลจะไม่ส่งจริง ดูข้อความที่ระบบจะส่งได้ที่ **ตั้งค่า > บันทึกการแจ้งเตือน**
ถ้าอยากจำลองว่าตู้เย็นผิดเกณฑ์ ให้พิมพ์ใน Console ว่า `MockAPI.force({'mock-fridge-1': 11})` แล้วกด "ดึงค่าเดี๋ยวนี้" 2 ครั้ง

ทดสอบ backend:

```bash
node tests/run.mjs
```

## เกณฑ์เริ่มต้น (แก้ได้ที่ ตั้งค่า > เกณฑ์ หรือกำหนดเป็นรายจุด)

| ประเภทพื้นที่ | ผิดเกณฑ์ (แจ้งทันที) | เฝ้าระวัง (แสดงสีเหลือง + อยู่ในสรุปรายวัน) |
|---|---|---|
| ห้องเก็บ/ขายยา | > 30°C | > 25°C, ความชื้น > 70% |
| ตู้เย็นเก็บยา | < 2°C หรือ > 8°C | – |

**ให้เภสัชกรยืนยันตัวเลขให้ตรงกับ SOP และข้อกำหนด GPP ที่ร้านใช้ก่อนเริ่มใช้งานจริง**

- ต้องผิดเกณฑ์ **ติดกัน 2 รอบ** ระบบจึงจะแจ้ง เพื่อกันแจ้งเตือนผิดตอนเปิดประตูตู้เย็นแป๊บเดียว ถ้ายังผิดเกณฑ์อยู่จะเตือนซ้ำทุก 60 นาที และแจ้งอีกครั้งเมื่อกลับเข้าเกณฑ์
- ถ้าไม่ได้รับค่าเกิน 30 นาที จะแจ้งว่า "ขาดการเชื่อมต่อ" และแจ้งอีกครั้งเมื่อกลับมาออนไลน์
- เหตุการณ์ผิดเกณฑ์ทุกครั้งต้อง **บันทึกการแก้ไข** ในหน้าเว็บ เพื่อเป็นหลักฐานตอนตรวจ GPP และจะไปปรากฏในรายงาน PDF
- **กราฟรายงาน:** มี 2 แบบ เลือกได้ที่หน้ารายงาน
  - **กราฟเส้น (X = วันที่):** อุณหภูมิเป็นเส้นสีเขียว อ่านค่าจากแกนซ้าย ความชื้นเป็นเส้นประสีน้ำเงิน อ่านค่าจากแกนขวา พิมพ์ A4 แนวนอน
  - **ตาราง (X = อุณหภูมิ):** จุดค่าลงในช่องตาราง พิมพ์ A4 แนวตั้ง
  - เลือกดูได้ทั้ง **รายเดือน** และ **กำหนดช่วงวันที่** (สูงสุด 93 วัน)
- **เมนู "ปรับกราฟ" (แอดมิน):**
  - **รอบเวลาอ่านค่า:** 1–4 รอบต่อวัน ค่าเริ่มต้นคือ เช้า 08:00–09:30 และบ่าย 13:00–14:00 ระบบใช้ค่าแรกที่วัดได้ในแต่ละช่วง
  - **สเกลแกนกราฟ:** ค่าต่ำสุด/สูงสุด/ช่องละ แยกตามประเภทพื้นที่ รวมถึงสเกลความชื้น และเลือกได้ว่าจะขยายสเกลอัตโนมัติหรือไม่
  - **รูปแบบเริ่มต้นของ PDF** และ **เกณฑ์** ของแต่ละประเภทพื้นที่
  - มีกราฟตัวอย่างจากข้อมูลจริงให้ดูก่อนกด "บันทึกค่าตั้งกราฟ" ค่าที่บันทึกเก็บใน Script Property `CHART_SETTINGS`
  - ค่าของแต่ละรอบเวลาคำนวณจากค่าดิบทุกครั้ง เปลี่ยนรอบเวลาแล้วจึงมีผลกับข้อมูลย้อนหลังด้วย
- **ค่าชดเชยการสอบเทียบ:** ให้เทียบเครื่องวัดกับเทอร์โมมิเตอร์ที่สอบเทียบแล้ว แล้วใส่ส่วนต่างที่หน้าแก้ไขเซ็นเซอร์

## ติดตั้งใช้งานจริง

### 1. เลือกและติดตั้งเครื่องวัด

**SwitchBot (แนะนำ เพราะ API ง่ายที่สุด)**
- ต้องมี **Hub Mini หรือ Hub 2 สาขาละ 1 ตัว** สำหรับห้องใช้ Meter / Meter Plus ส่วนตู้เย็นใช้ **Outdoor Meter** (กันน้ำ วางในตู้เย็นได้)
- ในแอป SwitchBot ให้เปิด **Cloud Service** ของเครื่องวัดทุกตัว
- ขอ token: แอป SwitchBot > Profile > Preferences > แตะ "App Version" 10 ครั้ง > Developer Options จะได้ **token** และ **secret**
- โควตา 10,000 ครั้งต่อวันต่อบัญชี ถ้าดึงทุก 15 นาที ใช้ได้ประมาณ 100 เครื่องต่อบัญชี ถ้ามีมากกว่านี้ให้แยกเป็นหลายบัญชี (เช่น บัญชีละ 1 จังหวัด)

**Tuya / Smart Life (ราคาถูก ไม่ต้องมี hub สำหรับรุ่น WiFi)**
- เพิ่มเครื่องในแอป Smart Life
- สมัครที่ https://iot.tuya.com > Cloud > Create Cloud Project แล้วเลือก Data Center ให้ตรงกับบัญชีแอป
- เพิ่ม API: IoT Core และ Authorization แล้วไปที่ Devices > Link App Account และสแกน QR ด้วยแอป Smart Life
- จดค่า **Access ID (clientId)**, **Access Secret** และ URL ของ Data Center (เช่น `https://openapi.tuyaus.com`)
- แพ็กเกจทดลอง (Trial) ของ IoT Core ต้องกดต่ออายุเป็นระยะ ถ้าหมดอายุ ระบบจะแจ้งว่าดึงข้อมูลไม่ได้เข้ากลุ่มส่วนกลาง

### 2. Google Sheet + Apps Script
1. สร้าง Google Sheet ใหม่ (เช่น "SalaTemp GPP") แล้วไปที่ Extensions > Apps Script
2. สร้างไฟล์ให้ครบตามโฟลเดอร์ `apps-script/` ได้แก่ `Code.gs`, `Store.gs`, `Providers.gs`, `Poller.gs`, `Alerts.gs`, `Reports.gs`, `ReportGrid.gs` และวางโค้ดลงไป
   จากนั้นเปิด Project Settings > "Show appsscript.json" แล้ววางเนื้อหาจาก `apps-script/appsscript.json` (time zone = Asia/Bangkok)
3. Project Settings > **Script Properties** ใส่ค่าต่อไปนี้

   | Property | ค่า |
   |---|---|
   | `CRED_SB1` (ตามชื่อ accountId) | `{"token":"...","secret":"..."}` |
   | `CRED_TY1` | `{"clientId":"...","secret":"...","baseUrl":"https://openapi.tuyaus.com"}` (ถ้าค่าอุณหภูมิผิดสเกล ให้เพิ่ม `"tempDiv":1`) |
   | `LINE_CHANNEL_TOKEN` | Channel access token (long-lived) ของ LINE OA |
   | `ALERT_EMAILS` | อีเมลสำรอง คั่นด้วย `,` (ใช้เมื่อ LINE ส่งไม่ได้หรือโควตาหมด) |
   | `APP_URL` | ลิงก์หน้าเว็บ (แนบท้ายข้อความแจ้งเตือน) |
   | `POLL_MINUTES` | (ไม่บังคับ) 5 / 10 / 15 / 30 ค่าเริ่มต้นคือ 15 |

4. เลือกฟังก์ชัน **`setup`** แล้วกด Run และอนุญาตสิทธิ์ ระบบจะสร้างชีตทั้งหมด ใส่เกณฑ์เริ่มต้น และตั้ง trigger (ดึงค่า / สรุป 08:00 / รายงานวันที่ 1)
5. ที่ชีต **Accounts** ให้เพิ่มแถวบัญชี เช่น `SB1 | switchbot | SwitchBot ภาคตะวันออก | TRUE`
6. Deploy > New deployment > Web app ตั้ง Execute as: **Me** และ Who has access: **Anyone** แล้วคัดลอก URL `/exec`

### 3. LINE Official Account
1. สร้าง LINE OA ที่ https://manager.line.biz แล้วเปิด Messaging API (จะได้ Channel ใน LINE Developers)
2. LINE Developers > Messaging API ให้ออก **Channel access token** แล้วใส่ใน `LINE_CHANNEL_TOKEN`
3. ตั้งค่า **Webhook URL** = URL `/exec` ของ Apps Script และเปิด Use webhook
   ปุ่ม Verify อาจแสดง error เพราะ Apps Script ตอบกลับด้วย redirect แต่ webhook ยังใช้งานได้ตามปกติ
4. เปิด "Allow bot to join group chats" แล้วเชิญ OA เข้ากลุ่ม LINE ของแต่ละสาขา และกลุ่มเภสัชกรส่วนกลาง
   (ถ้าเชิญไว้ก่อนตั้ง webhook ให้พิมพ์ `#ลงทะเบียน` ในกลุ่ม)
5. หน้าเว็บ > ตั้งค่า > กลุ่ม LINE: เลือกสาขาให้แต่ละกลุ่ม (กลุ่มส่วนกลางให้เลือก "ทุกสาขา") แล้วกด **ทดสอบ**

**โควตา:** แพ็กฟรีส่งได้จำนวนจำกัดต่อเดือน และ **การส่งเข้ากลุ่มนับตามจำนวนสมาชิกในกลุ่ม**
ระบบรวมทุกเหตุการณ์ในรอบเดียวกันเป็นข้อความเดียวต่อกลุ่มอยู่แล้ว ดูยอดที่ใช้ไปได้ที่ ตั้งค่า > "ดูโควตา LINE" ถ้าไม่พอให้เปลี่ยนเป็นแพ็กที่สูงขึ้น หรือลดจำนวนสมาชิกในกลุ่มที่รับแจ้งเตือน

### 4. หน้าเว็บ (GitHub Pages)
1. แก้ `config.js` ใส่ `APPS_SCRIPT_URL` = URL `/exec`
2. push ขึ้น GitHub แล้วเปิด Pages
3. Google Cloud Console > OAuth Client (ตัวเดียวกับระบบแจ้งซ่อม) ให้เพิ่ม origin `https://<user>.github.io`
4. เข้าเว็บด้วยบัญชีแอดมิน > ตั้งค่า > **เพิ่มเซ็นเซอร์** > เลือกบัญชี > กด **ค้นหา** > เลือกอุปกรณ์ > เลือกสาขา/จุดติดตั้ง/ประเภท
5. พนักงานลงทะเบียนครั้งแรกเองผ่านหน้าเว็บ แล้วแอดมินอนุมัติโดยแก้คอลัมน์ `status` เป็น `approved` ในชีต **Users** (แอดมินเพิ่มเติมใส่ในชีต AdminEmails)

## ข้อมูลเก็บที่ไหน
- **ชีตหลัก:** Sensors (สถานะล่าสุด + ค่าสะสมของวันนี้), Excursions (เหตุการณ์ + การแก้ไข), Daily (สรุปรายวัน ใช้ทำรายงาน), AlertLog, LineTargets
- **ค่าดิบ:** ไฟล์ `SalaTemp_Readings_YYYY-MM` ในโฟลเดอร์ Drive `SalaTemp_Data` สร้างใหม่ทุกเดือนและแยกแท็บตามสาขา เพื่อไม่ให้ชนลิมิต 10 ล้านเซลล์ของ Sheets
- **รายงาน PDF:** โฟลเดอร์ Drive `SalaTemp_Reports/YYYY-MM` (ให้สิทธิ์ดูโฟลเดอร์นี้กับคนที่ต้องเปิดลิงก์จาก LINE)

## ข้อจำกัดที่ควรรู้
- Apps Script บัญชี Gmail ทั่วไปเรียก UrlFetch ได้ 20,000 ครั้งต่อวัน (SwitchBot 100 เครื่องที่รอบ 15 นาที ใช้ประมาณ 9,600 ครั้ง) และแต่ละครั้งทำงานได้ไม่เกิน 6 นาที
- Apps Script อ่าน header ลายเซ็นของ LINE webhook ไม่ได้ ระบบจึงแค่บันทึก groupId ไว้ให้แอดมินเลือกผูกเอง ไม่มีการส่งข้อมูลออกจาก webhook
- ถ้าตั้ง `minIntervalMin` ของบัญชีไว้นานกว่า 30 นาที เซ็นเซอร์ในบัญชีนั้นจะขึ้น "ขาดการเชื่อมต่อ" ระหว่างรอบ
- เครื่องวัดราคาประหยัดไม่มีใบสอบเทียบ ควรเทียบกับเทอร์โมมิเตอร์ที่สอบเทียบแล้วปีละครั้ง และใส่ค่าชดเชย
